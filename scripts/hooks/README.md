# `scripts/hooks/`

**The in-session hooks the CLI runs on a session's commands, edits and worktrees, the module they
share, and the selftests that hold each guard to what it refuses.** They are the first tier of
`AGENTS.md` § "The gate ladder". `.harness/hooks.json` registers them, and
`scripts/render-integrations.mjs` renders that file for each CLI a project selects in
`.harness/integrations.json`. The two worktree hooks render for Claude Code alone: Codex, Copilot
and OpenCode get no WorktreeCreate or WorktreeRemove hook (`tools/integrations/selftest.mjs`).

Each file opens with a header, and that header is the authority on it: where a row here and a
header disagree, the header wins and the row is corrected. `AGENTS.md` § "Standing rules for prompts
and gates" asks each header for four parts. The headers of `worktree-create.mjs` and
`worktree-remove.mjs` lack the invocation and the needs, which ss-03i carries.

| File | What it is, or for a guard, what it refuses |
|---|---|
| `_shared.mjs` | The helpers the hooks import: the repository root and the trunk's name; the payload read from stdin and the paths an edit targets; a file's header, whether it carries a generator's banner, and the prose files the banner check skips; which checkout a directory or an edited path is in; and git's environment with no inherited `GIT_*` variable. It loads Node's built-ins alone and starts no process when it is loaded. |
| `block-generated-edit.mjs` | Before an edit, it refuses a Write, Edit or Codex patch to a file whose header carries a generator's "do not edit by hand" banner. It reads the header on disk, or the incoming text for a file that does not exist yet, so a new file that claims to be generated is refused too. Prose files (`.md`, `.mdx`, `.txt`, `.rst`, `.adoc`) are exempt. Its refusal says to find the tool the banner names and change it there. `mise run integrations:selftest` holds it. |
| `guard-delivery.mjs` | Before an edit, it refuses a change to a protected test. It refuses an edit to the protected-tests list that drops one of HEAD's paths, and a patch that deletes, moves or overwrites the list file. It refuses every path outside `beforeApprovalPaths` on a feature's or an epic's branch, and on a story's branch until the feature's spec on `origin/main` says `Design approved` or `Shipped`. It refuses the same on a fan-out lane's `agent/agent-<hash>` branch until the lane renames it to name its issue. |
| `guard-delivery.selftest.mjs` | The delivery guard's cases over a scratch repository with a stub `bd`: protected-test edits by Edit, Write and Codex patch, Gate 2 on a story's and a feature's branch, and the guard failing open with no `bd` or a `bd` that errors. `mise run guard-delivery:selftest` runs it. |
| `guard-delivery-lane.selftest.mjs` | The protected test that reproduces ss-pq2. Code on a fan-out lane's `agent/agent-<hash>` branch is refused until the lane renames the branch to name its story, and is then held at Gate 2. `mise run guard-delivery:selftest` runs it beside the guard's other cases. |
| `guard-git.mjs` | Before a command. From a linked worktree it refuses a push to `main` or `release`, `git push --all` and `--mirror`, a switch to or a rewrite of either branch, a merge of either into the branch, a merge whose directory it cannot resolve, `git worktree`, `git gc`, `git prune`, `git reflog expire`, a `gh pr merge` other than `--auto` or `--disable-auto`, and a payload it cannot read. Everywhere it refuses a bare `git worktree prune`. It refuses a merge into the primary checkout unless `main` is checked out there and the merge is `--ff-only`, beside options that change no result, or ends a merge under way. It refuses a `gh pr create` without `--base main`, and one whose `gh` is not a script that opens with `#!` and names `scripts/github-app-token.mjs token`, as `.devcontainer/gh` and `scripts/gh` do; a policy that names no App turns that rule off. It refuses `gh pr review --approve`, `gh pr merge --admin`, and graphify's `update`, `watch`, `hook install` and `claude install`. It refuses a `git commit` or `git revert` on a branch under `refs/heads/agent/` whose author or committer would not be the App's bot, judging the author that `--author`, a cherry-pick under way, `-C`, `-c` or `--amend` keeps. Where it cannot read the bot from the policy it refuses every such commit, and a policy that names no App turns that rule off. It does not judge a commit on a detached HEAD or in a directory it cannot resolve. It misses a git behind `env`, `command`, `nohup` or `time`, a git alias, and an identity set through `--config-env` or `GIT_CONFIG_COUNT`. In a stray worktree directory it refuses every git call. |
| `guard-git-app-form.selftest.mjs` | The protected test that reproduces ss-34a. The host's form of `gh pr create` that the git guard's refusal names must be one the guard allows. Run with a token helper that cannot mint, it must run no `gh` with an empty token. |
| `guard-git-commit.selftest.mjs` | The git guard's commit-identity rule over scratch lanes on `agent/` branches, where a global git config gives the operator's identity. A commit passes when the bot's identity comes from the four variables, `-c` options, the session's environment or a global git config. The dispatcher's cherry-pick and the briefing's rebase pass too. A commit or a revert whose author or committer is not the bot is refused, the author that `--amend`, `-C`, `-c` or a cherry-pick under way keeps included. The rule fails closed on a policy it cannot read, and is off under one that names no App. |
| `guard-git-host-gh.selftest.mjs` | `scripts/gh`, the host's form that the git guard's refusal names, with a stub `gh` and a stub of GitHub's endpoint. Each way the mint fails runs no `gh` and prints the helper's reason for it. The wrapper skips itself when the clone's `scripts/` comes first on PATH or an empty PATH entry finds it, and ignores an exported `CDPATH`. With no other `gh` on PATH it runs nothing and says so. It is not protected. |
| `guard-unprovisioned-worktree.mjs` | Before a command, it refuses every command in a linked worktree whose branch is not `agent/<name>`, which is a worktree `scripts/new-worktree.sh` did not make. |
| `worktree-create.mjs` | The WorktreeCreate hook. It makes the `EnterWorktree` tool provision its worktree through `scripts/new-worktree.sh`, off `origin/main` and onto `agent/<name>`, with ports and a briefing. |
| `worktree-hooks.selftest.mjs` | The worktree hooks and the unprovisioned-worktree guard over a scratch repository, and these git guard rules: `git worktree` and a push to `main` from a worktree, a stray worktree directory, an inherited `GIT_DIR`, the PR base, the App rule, an approval, a merge past the checks or now, a bare `git worktree prune`, a merge into the primary checkout, and graphify. The guard's switch, merge-of-`main`, object-store, `push --all` and unreadable-payload rules have no case yet (ss-y98). It also renders the briefing from its template, runs `scripts/new-worktree.sh` beside a held lock, and loads every rendered Claude hook from another directory. `mise run worktree:selftest` runs it beside the three git guard selftests. |
| `worktree-remove.mjs` | The WorktreeRemove hook. It removes a worktree's checkout, and deletes the directory itself where the sandbox keeps `git worktree remove` from finishing. It never deletes the branch. |
